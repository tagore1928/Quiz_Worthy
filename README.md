**Quiz Worthy** is a technical interview practice platform. Pick a computer-science topic and take a 10-question multiple-choice quiz generated by AI at your current difficulty level. Every answer comes with an explanation, and your progress (XP, topic levels, badges, activity) is tracked over time.

---

## Features

- **AI-generated quizzes**: 10 questions per session, generated by Groq (`openai/gpt-oss-120b`, falling back to `openai/gpt-oss-20b`), validated and with shuffled answer options.
- **Curated offline question bank**: if AI generation is unavailable, the API serves 100 hand-written questions (10 per built-in topic), and the quiz shows an "Offline set" badge.
- **10 built-in topics**: Operating Systems, Computer Networks, DBMS, Python, Java, C++, Frontend, Backend, Machine Learning, DSA, plus custom topics added by admins.
- **Adaptive difficulty**: each topic has a level from 1 to 3. Scoring 0–40% sets level 1, 41–70% level 2 and 71–100% level 3 for the next quiz.
- **Gamification**: XP per quiz, Silver badges for completing a day's task checklist, a Gold badge after 50 active days.
- **Daily Tasks** checklist and a 365-day **activity heatmap** (dates in IST).
- **Analytics**: topic-mastery radar chart, score history chart and paginated attempt history.
- **Leaderboards**: global and per-institution rankings.
- **Admin panel**: user search and level resets, custom topic management, support/topic request feed and maintenance mode.
- **Authentication**: email/password with email verification, or Google sign-in with an onboarding step.
- **Dark, futuristic UI**: graphite surfaces with a single acid-lime accent, Geist and Geist Mono type, responsive down to phone width.

## Architecture

```plaintext
Browser (React SPA)
  ├── Firebase Auth ............ sign-up, login, Google sign-in, email verification
  ├── Cloud Firestore .......... profiles, attempts, tasks, activity, topics, settings
  └── POST /api/quiz/generate ─► Express API (backend/)
                                   └── groqQuizService
                                         ├── Groq: gpt-oss-120b → gpt-oss-20b
                                         └── fallback: curated offline question bank
```

**Quiz flow**

1. `QuizArena` reads your level for the topic and calls `POST /api/quiz/generate` with `{ topic, level }`.
2. The backend asks Groq for strict JSON, validates every question (4 distinct options, a valid `correctIndex`), strips Markdown code fences and shuffles the options.
3. If every model fails, it serves the offline bank (`source: "offline"`). Topics without curated questions return HTTP 503 with a message, and the UI offers **Try Again**.
4. When you finish, the browser saves XP, the new topic level, the attempt and the day's activity to Firestore, then refreshes your profile.

**Firestore collections**

| Path | Contents |
| :--- | :--- |
| `users/{uid}` | Profile: name, institution, role, XP, badges, streak, `topicLevels` |
| `users/{uid}/quiz_attempts` | Score, percentage, previous and new level per quiz |
| `users/{uid}/daily_todos/{date}` | Daily task checklist (IST date) |
| `users/{uid}/activity/{date}` | Daily activity for the heatmap |
| `topics` | Custom topics created by admins |
| `topic_requests` | Support messages and topic requests |
| `system/settings` | `maintenanceMode` flag |

Access is controlled by [`firestore.rules`](firestore.rules).

## Getting started

### Prerequisites

- [Node.js](https://nodejs.org/) 18 or newer and npm
- A [Groq API key](https://console.groq.com/)
- A [Firebase project](https://console.firebase.google.com/) with Authentication (Email/Password and Google) and Cloud Firestore enabled

### 1. Clone

```bash
git clone https://github.com/tagore1928/Quiz_Worthy.git
cd Quiz_Worthy
```

### 2. Configure environment variables

`backend/.env` (copy from `backend/.env.example`):

```bash
GROQ_API_KEY=your_groq_api_key
# Optional: comma-separated Groq models to try in order
# (default: openai/gpt-oss-120b,openai/gpt-oss-20b)
GROQ_MODEL=
PORT=5000
CLIENT_URL=http://localhost:5173
```

`frontend/.env` (copy from `frontend/.env.example`):

```bash
VITE_FIREBASE_API_KEY=your_firebase_api_key
VITE_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=your_project_id
VITE_FIREBASE_STORAGE_BUCKET=your_project.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=your_messaging_sender_id
VITE_FIREBASE_APP_ID=your_app_id
# Optional: API origin in production (leave empty locally to use the Vite proxy)
VITE_API_BASE_URL=
```

Without a Groq key the app still works, using the offline question bank for the built-in topics.

### 3. Install dependencies

```bash
npm run install:all
```

### 4. Run locally

```bash
npm run dev
```

- App: <http://localhost:5173>
- API: <http://localhost:5000>
- Health check: <http://localhost:5000/api/health>

## Deployment (Vercel)

`vercel.json` defines two services in one project:

- **frontend**: Vite app in `frontend/`
- **backend**: Express app with entry point `backend/src/index.ts`

Requests to `/api/*` are routed to the backend, and everything else to the frontend. A `Cross-Origin-Opener-Policy: same-origin-allow-popups` header keeps Google sign-in popups working.

Set these environment variables in the Vercel project:

- `VITE_FIREBASE_*` for the frontend
- `GROQ_API_KEY` for the backend, and optionally `GROQ_MODEL`. If an old `GROQ_MODEL` pointing to a Llama 3.x model is set, remove it: those models are no longer available.

Also add your production domain under **Firebase Console → Authentication → Settings → Authorized domains**.

## Known limitations

- Groq's free tier allows about 8,000 tokens per minute on `gpt-oss-120b` (a quiz uses roughly 2,000). Under heavier load the API falls back to `gpt-oss-20b` and then to the offline bank.
- Firestore rules currently let users update any field on their own profile, including XP and role. Restrict this before opening the app widely.
- Daily streaks are not yet calculated (`currentStreak` stays at 0).
